# ESG-Insight Agent 产品定位文档

> 目的：把项目从“ESG 报告问答 Demo”收敛为一个面向真实痛点的 AI 应用项目，作为后续开发、论文和面试讲述的统一依据。
>
> 当前版本：v0.1  
> 更新日期：2026-08-06

---

## 1. 项目一句话定位

**ESG-Insight Agent 是一个面向投资研究 / ESG 分析场景的可评测 ESG 报告分析智能体系统，重点解决 ESG 报告长文本、披露不完整、口径不一致和潜在绿漂风险难以人工批量识别的问题。**

更偏论文表述：

> 基于评测驱动工作流的 ESG 报告分析智能体系统。

更偏面试表述：

> 我做的不是一个简单 RAG 问答系统，而是一个“能拿证据、能做结构化判断、能被评测和持续调优”的 ESG 报告分析 Agent。

---

## 2. 为什么选择 ESG 报告分析

### 2.1 个人背景匹配

项目起点来自我的复合背景：本科是**金融工程 + 计算机科学与技术**双学位，同时有金融证券公司相关实习经历。因此我对企业披露文件的结构和分析方式有一定了解。

可在面试中举的例子：

- **年报 / 财报分析**：关注资产负债表、利润表、现金流量表，例如营收增长率、毛利率、资产负债率、经营现金流净额等指标，用来判断盈利能力、偿债能力和经营质量。
- **招股说明书分析**：关注主营业务、募投项目、关联交易、风险因素、客户集中度等内容，用于判断企业上市前的信息披露质量和潜在风险。
- **债券募集说明书分析**：关注偿债来源、担保措施、评级情况、现金流覆盖能力等，用于评估信用风险。
- **ESG 报告分析**：关注碳排放、能源消耗、员工权益、安全生产、供应链责任、治理结构等非财务信息，用于评估企业长期可持续发展能力和潜在声誉 / 合规风险。

### 2.2 ESG 报告的特殊价值

ESG 报告与绿色经济、双碳目标、可持续发展、绿色金融等趋势高度相关。相比传统财报，ESG 报告中包含大量非财务但可能影响企业长期价值的信息，例如：

- 碳排放总量和排放强度；
- 可再生能源使用比例；
- 绿色项目或绿色金融规模；
- 供应链劳工与环境责任；
- 安全生产事故；
- 董事会治理结构；
- 第三方鉴证情况。

这些信息可能被投资机构、ESG 评级机构、监管方和企业自身消费，用于风险评估、同行对标和披露改进。

## 3. 目标用户与消费场景

### 3.1 主用户

**投资研究员 / ESG 分析师 / 券商研究助理**。

这类用户需要快速阅读大量公司 ESG 报告，并回答：

- 某公司某项 ESG 指标是否披露？
- 多年披露是否连续？
- 同行业公司之间是否可比？
- 报告中是否存在“口号多、数据少”的潜在绿漂风险？
- 结论是否有页码和原文证据支撑？

### 3.2 次级用户

| 用户 | 使用价值 |
|---|---|
| ESG 评级机构 | 批量检查企业披露质量，辅助分析师初筛 |
| 投资机构 | 在投资研究中快速发现 ESG 风险敞口 |
| 企业 ESG 部门 | 对标同行，发现自身披露短板 |
| 监管 / 咨询机构 | 检查披露完整性、一致性和证据充分性 |

### 3.3 明确不做的事情

为了避免项目边界发散，本项目暂不做：

1. 不做股票买卖建议；
2. 不替代完整 ESG 评级；
3. 不声称判断企业真实 ESG 表现，只判断“报告披露质量”和“文本证据支撑程度”；
4. 不做大规模实时爬虫；
5. 不以微调大模型作为第一优先级。

## 4. 核心业务问题

ESG 报告分析的真实痛点可以概括为四个字：**长、散、虚、难比**。

| 痛点 | 说明 | Agent 价值 |
|---|---|---|
| 长 | ESG 报告动辄百页，文本量大 | RAG + 长文本压缩帮助定位关键信息 |
| 散 | 指标分散在不同章节，格式不固定 | SQL + RAG 双通道整合结构化和非结构化证据 |
| 虚 | 大量理念性、宣传性表述，数据支撑不足 | 绿漂风险识别，判断 claim-evidence mismatch |
| 难比 | 不同公司 / 年份口径不一致，人工横纵向对比困难 | 披露质量评分和可比性检查 |

## 5. 核心功能定义

### 5.1 ESG 事实抽取

目标：从 ESG 报告中抽取关键指标，并返回结构化证据。

示例问题：

> 提取比亚迪 2022-2024 年碳排放相关指标。

期望输出：

| 公司 | 年份 | 指标 | 数值 | 单位 | 页码 | 原文证据 | 置信度 |
|---|---:|---|---:|---|---:|---|---:|

### 5.2 披露质量评分

目标：判断报告披露是否完整、连续、可比、可验证和具体。

建议评分维度：

| 维度 | 权重 | 说明 |
|---|---:|---|
| 完整性 | 30 | 是否披露核心指标 |
| 连续性 | 20 | 是否多年连续披露 |
| 可比性 | 20 | 单位、范围、口径是否一致 |
| 可验证性 | 20 | 是否有页码、原文证据、第三方鉴证 |
| 具体性 | 10 | 是否有明确目标和量化进展 |

### 5.3 绿漂风险识别

目标：识别报告中“表述很强，但证据较弱”的内容。

风险类型：

| 风险类型 | 说明 |
|---|---|
| 空泛承诺 | 只有理念，没有指标 |
| 目标无进展 | 有目标，没有年度进展 |
| 选择性披露 | 只披露好看的数据，不披露关键数据 |
| 口径漂移 | 不同年份指标口径变化导致不可比 |
| 证据不足 | 重大结论缺少数据、页码或第三方鉴证 |

核心方法：

> 将绿漂风险建模为 claim-evidence mismatch：先抽取强 ESG 表述，再检查其附近是否存在数字、时间、范围、进展、第三方验证等证据。如果表述强而证据弱，则标记为潜在风险。

### 5.4 横向 / 纵向对比

目标：支持同公司不同年份纵向对比，以及同年同行业多公司横向对比。

重点不是给出泛泛结论，而是指出：

- 哪些数据可比；
- 哪些数据不可比；
- 不可比原因是什么；
- 缺失数据是否影响结论可信度。

## 6. 项目核心方法论

本项目的核心不是堆技术，而是形成一条完整链路：

```text
业务痛点
  ↓
任务拆解
  ↓
白盒 Agent Workflow
  ↓
SQL + RAG 双通道证据获取
  ↓
Evaluator-D 数据质量检查
  ↓
披露质量评分 / 绿漂风险识别
  ↓
Evaluator-O 输出事实性检查
  ↓
自动化评测集
  ↓
Bad Case 归因
  ↓
修复与回归测试
```

最终目标是证明：

> 在 ESG 报告这种长文本、非结构化、口径不一致的场景中，评测驱动的白盒 Agent Workflow 比黑盒 ReAct Agent 更可靠、更可调试、更适合落地。
