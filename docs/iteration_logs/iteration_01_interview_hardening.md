# Iteration 01：秋招展示向工程化加固

日期：2026-08-08

## 目标

把项目从“能跑的 ESG Agent”升级为“面试官能快速看懂亮点、能看到质量工程闭环、能验证边界”的个人项目。

## 本轮改动

1. **新增 README 门面**
   - 明确项目定位：可评测 ESG 分析 Agent，而不是普通 PDF 问答。
   - 补充架构图、快速开始、示例问题、评测命令和面试讲述重点。

2. **新增披露质量评分模块** `agent/disclosure_quality.py`
   - 使用确定性 Rubric：完整性 30、连续性 20、可比性 20、可验证性 20、具体性 10。
   - 输出 0-100 分、等级、维度拆解和潜在绿漂 / 披露风险信号。
   - 集成到 `synthesizer`，每次复杂分析都会附带评分 Appendix。

3. **新增项目能力与覆盖边界接口** `GET /api/capabilities`
   - 扫描本地 PDF、SQLite 表和数据字典。
   - 明确展示支持公司、年份、行业、表结构和已知边界。
   - 面试时可用于说明“系统知道自己能答什么，不能答什么”。

4. **前端展示增强**
   - 修复 JS 中中文乱码和节点状态判断优先级问题。
   - 新增披露质量评分卡片，让质量评分在 Demo 中一眼可见。

5. **工程化入口**
   - 新增 `.env.example`、`Makefile`。
   - 新增 `tests/`，覆盖披露质量评分和能力接口形状。

## 面试表达

> 本轮我重点补齐了“质量可度量”和“项目可展示”两个短板。原系统能回答 ESG 问题，但面试官不一定能立刻看到它和普通 RAG 的差异。现在系统每次回答都会给出披露质量评分和风险信号，并通过 `/api/capabilities` 明确自身证据覆盖边界，体现了 AI 应用里非常重要的 reliability mindset。

## 验证

```bash
python3 -m compileall agent api scripts tests
python3 -m unittest discover -s tests
```

结果：3 个单元测试通过。
