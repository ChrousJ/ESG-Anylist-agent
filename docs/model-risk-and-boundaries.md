# 模型风险与业务边界

> 用途：回答面试官关于 ESG、绿漂、金融合规和模型误判的追问。  
> 更新日期：2026-08-09

---

## 1. 项目不做什么

本项目定位为 **ESG 报告分析辅助工具**，不是：

- 投资建议系统；
- 企业 ESG 最终评级系统；
- 法律意义上的绿漂认定系统；
- 完全自动化审计系统；
- 覆盖全市场、全指标、全年份的数据平台。

面试中不要说“系统判断企业绿漂”，应该说：

> 系统识别 ESG 报告中需要人工复核的 claim-evidence mismatch。

---

## 2. 为什么不能直接判断企业真实绿漂

判断真实绿漂通常需要：

- 企业完整披露；
- 第三方审计或鉴证；
- 监管口径；
- 行业基准；
- 实地运营数据；
- 多来源交叉验证。

当前项目只有公开 ESG 报告、结构化指标库和本地 PDF，因此不具备最终定性的证据条件。

所以第一版绿漂风险雷达只做：

```text
报告文本中的强 ESG 表述
+ 附近缺少数字 / 年度进展 / 同比变化 / 第三方鉴证
= 潜在人工核查点
```

---

## 3. 主要模型风险

| 风险 | 表现 | 缓解方式 |
|---|---|---|
| 数字幻觉 | 回答中出现证据里没有的数字 | SQL 结构化查询 + Evaluator-O 数字检查 |
| 实体越界 | 用户问 A 公司，回答混入 B 公司 | context 实体抽取 + Evaluator-O 实体一致性检查 |
| 趋势误判 | 数据上升却说下降 | 趋势计算 / Evaluator-O 趋势校验 |
| 证据不足硬答 | SQL/RAG 都没数据仍生成结论 | Evaluator-D + degraded response |
| RAG 召回偏移 | 检索到宣传页而非指标页 | query rewrite、rerank、bad case 归因 |
| 绿漂误判 | 把所有宣传话术都标成风险 | 只输出人工核查点，要求解释 evidence gap |
| 缺失误读 | 把未披露当作 0 | Data Card 明确缺失处理原则 |

---

## 4. 当前安全策略

### 4.1 明确数据边界

通过 `/api/capabilities` 暴露当前覆盖范围。

### 4.2 证据不足时降级

当 SQL 和 RAG 都无法提供有效证据时，系统应该输出安全响应，而不是硬生成。

### 4.3 绿漂风险只做窄定义

不输出：

```text
这家公司存在绿漂。
```

输出：

```text
该段表述属于强 ESG claim，但附近缺少量化指标、年度进展或第三方鉴证，建议人工复核。
```

### 4.4 不输出投资建议

不根据 ESG 信息给出买入、卖出、持有建议。

## 5. 面试问答

### Q1：绿漂检测会不会误伤企业？

会有风险，所以我没有把它设计成最终定性系统，而是设计成“人工核查点发现器”。第一版只检测强表述附近是否缺少证据，并把 evidence gap 写出来，最终判断仍需要人工分析师结合更多数据。

### Q2：为什么不用 LLM 直接判断披露质量？

LLM judge 可作为后续复核，但第一版我选择确定性 Rubric，因为它可解释、可复现、可单元测试。面试和工程落地中，稳定可回归比主观打分更重要。

### Q3：如果公司没披露某个指标，系统会不会认为它表现差？

不会。系统区分“未披露”“当前数据未覆盖”和“数值为 0”。未披露只能说明证据不足，不能直接推断企业表现差。

### Q4：金融场景怎么降低幻觉？

我主要做了三层：第一，结构化数字走 SQL；第二，原文解释走 RAG 并保留来源；第三，用 Evaluator-D/O 在生成前后做质量检查，证据不足时降级。

---

## 6. 后续风险治理方向

- 引入人工标注集，评估绿漂风险 precision / recall；
- 引入 LLM-as-a-Judge 作为第二层复核，而不是唯一判断器；
- 对每个风险点输出置信度和证据缺口类型；
- 对高风险输出增加免责声明；
- 接入第三方 ESG 数据或审计信息做交叉验证。
